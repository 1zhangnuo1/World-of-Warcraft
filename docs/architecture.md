# 设计说明：从二维闭环到三维导航

## 目标与整体边界

把“知道去哪儿、怎么走、是否真的在走”分开。第一阶段用本地网格验证导航闭环；核心代码不接游戏进程、键鼠注入、网络或任何外部游戏接口。

依赖方向为 `app → presentation / simulation → adapters → core`。`core` 只依赖 Python 标准库，表示可复用的决策逻辑；`presentation` 只调用模拟对象和读取状态，绝不决定哪里可走。

## 基础组件及职责

1. `SearchGraph[Node]` 定义节点是否存在、相邻节点与代价、启发距离。A* 使用哈希节点，不要求坐标元组，也不要求节点支持大小比较。非负代价与可采纳的启发式是最优性的前提，启发式设为零即可退化为 Dijkstra。
2. `NavigationBackend` 把世界位置转换成可执行路点。`plan()` 返回 `Route` 或无路；`route_is_valid()` 检查剩余路径；`can_traverse()` 检查实际运动段；`revision` 在可通行性变化时递增。
3. `MotionDriver` 接收目标和时间步，提供实际 `position`。它可以不响应命令，因此控制器不能把“发了指令”当成“已经移动”。模拟执行器持有连续 Vec3 坐标并做运动段碰撞检测。
4. `StuckDetector` 用锚点位移与模拟时间识别停滞，过滤小于 0.06 格的抖动。长期缓慢爬行低于阈值也会判为无有效进展；未来不同运动速度需配置阈值。
5. `NavigationController` 连接规划、执行和反馈，维护 `idle / moving / recovering / waiting / arrived` 状态。`recovering` 表示因卡死重新规划、等待实际移动恢复；`waiting` 表示当前无路。

接口不通过插件注册表或全局服务定位器解析；在 `Simulation` 构造处直接注入，便于单测和逐步替换。

## 实际工作流程

GUI 使用 60Hz 固定模拟步长。渲染帧时间通过累加器转换成模拟步；最大累计单帧时间为 0.25 秒，拖动窗口或调试暂停后不突然追赶很长时间。无窗口模式使用相同步长快速推进。

每个模拟步处理到期障碍、随机挡路和移动故障，然后更新控制器。地图版本变化时，检查从**实际位置**到剩余路点的所有运动段。路线已堵则调用 A*；仍可走则不浪费一次规划。即使没有地图变更，执行器也会在实际移动前做碰撞检查。

例子：Agent 正从 (3,3) 走到 (4,3)，现在位于 (3.25,3)。若 (4,3) 突然被挡，控制器会从实际所在的 (3,3) 格重新规划，先回到 (3,3) 中心，再走可用分支。这个回退经过实际运动，不会瞬移、不抄对角线、不穿过墙角。矩形相交检测覆盖整个运动段，较大时间步也不能穿过障碍。

卡死例子：地图没有变化，但执行器被冻结；控制器仍尝试跟随路径，实际反馈坐标保持不变。超过阈值后记录 `stuck`，重新规划，进入恢复状态。如果故障没有解除，规划可能得到相同路线，这是正确且明确的限制：规划器不能修复物理执行器。演示故障会在指定时长后自动解除，届时继续沿新路线行走。

无路不被当成卡死：控制器清空路线，进入等待，定期重试并监听地图版本变化。有限次数的临时障碍最终消失，基准地图保持连通。用户手动放置的永久障碍可能把目标彻底封死，此时保持等待是合理行为。

到达条件只检查实际位置和目标位置，距离容差为 1e-6；模拟执行器在一步能到达时精确落在路点上。未来有观测噪声的执行器需要将此容差改为可配置的到达半径，并更新相关验收测试。

## 3D Navmesh 接入建议（尚未实现）

第一步新增 `adapters/navmesh.py`：实现世界坐标定位到多边形、多边形邻接图、可行走条件和地图更新版本。网格的 Manhattan 启发式只在 `GridMap` 中存在；Navmesh 应用自己的距离 / 代价模型。

第二步从多边形路径计算走廊和可执行路点，通常需要 funnel 或其他平滑算法。`NavigationBackend.plan()` 的输出仍然是世界坐标 `Route`。同时实现地面投影、Agent 半径、坡度、层高和整段碰撞检查。仅使用当前 Vec3 类型并不代表已有三维导航。

第三步替换 `MotionDriver`，从实际系统采样位置反馈；将输入动作、速度约束和执行错误封装在执行器中。基于位置的卡死检测可以复用，复杂场景还需目标距离进展、振荡识别、恢复动作策略和失败上限。

第四步替换显示适配器，保留无窗口回归。当前 A* 同步运行，225 格成本很低；大型 Navmesh 应另行设计异步规划、取消、规划结果版本校验与局部重规划。

## 当前明确取舍

- 单 Agent，无多 Agent 避碰或动态障碍运动预测。
- 碰撞体为点，红点绘制半径只是视觉大小。
- 自动障碍随机选择当前路径中的候选格，以稳定演示失效与恢复，不代表环境感知。
- 固定墙不开放编辑；自动障碍有 TTL，手动障碍持续存在。
- 事件和轨迹使用有上限的队列；JSON 的事件是最近 80 条，累计次数独立保留。
- 界面优先选系统中文字体，无中文字体则自动切换英文，不依赖本机绝对字体路径。
- 构建脚本以自身位置定位项目根目录，支持中文、空格路径；所有调用用参数列表传递。
- Windows 配置及 CI 已提供，但只有在 Windows 真正运行测试 / 构建后才能宣称通过该平台验证。
